# Results — LOB ML baseline: top-of-book features to mid-price direction

Model layer only (no simulation), so the Naive / ProbQueue / latency columns of the standard table do not apply.

| 项 | 原文 | 本平台 (Naive) | 本平台 (ProbQueue) | 延迟 1ms | 延迟 10ms |
|---|---|---|---|---|---|
| up/down hit rate @1 event | 70–80 % (K&Z, NASDAQ) | see tables below | n/a | n/a | n/a |

Command: `python -m papers.lob_ml_baseline.evaluate --config papers/lob_ml_baseline/configs/<base|btc|smoke|smoke_btc>.yaml`
(`configs/*.yaml` carry dataset, symbol, window, horizons, feature and model params, out dir; any key can be
overridden on the CLI, e.g. `--dataset <ds> --symbol <sym> --start ISO --out DIR`). This paper has no strategy
and no simulation, so `hft run` does not apply to it.
Outputs: `results/<ds>_<sym>_summary.json` (all metrics + coefficients), `results/<ds>_<sym>_ridge_signal_report.html`.

Features (12): spread, top imbalance, depth imbalance, microprice − mid, mid returns over 1/5/10 rows,
realized vol (50), trade sign, seconds since last row, `ofi_e1`, `ofi_e10` (`hft.features.ofi.OFI`).

Columns: `acc` = 3-class accuracy of balanced logistic regression on test; `major` = accuracy of always
predicting the train majority class; `mF1` = macro-F1; `hit` = up/down hit rate on test rows where both
truth and prediction are non-flat; `cover` = share of non-flat rows the model calls non-flat; `flat` = flat
share of test; `ridge R²` = Ridge R² on test; `IC` = Spearman IC of the Ridge score vs the continuous label
on test; `IC_t` = t-stat of IC over 10 time buckets. Split 70/30 by time, embargo = max label horizon in rows.
Features and labels are built per contiguous segment (row gap > 5 s = data hole); nothing bridges a hole.

## Caveats

- **Sample.** One instrument, one day, ~10k test rows of which 7–28 % are non-flat depending on horizon.
  IC_t of 15–18 at ≤ 10 ev is well past noise; 50 ev / 5 s (IC_t ≈ 8) rests on ~2.5k non-flat rows.
- **One Binance row = one 100 ms diff batch** (median 27 deltas), not one event. "1 event" horizons are
  ~100 ms; the literature's per-message horizons are finer.
- **Mechanical, not tradeable.** The 1-row hit rate is dominated by queue depletion: when the best level is
  nearly empty, the next top-of-book change is almost surely that level vanishing. It predicts the sign of
  the next half-tick move, which is inside the spread. No cost model was applied.
- Balanced class weights push 3-class accuracy below the majority baseline at short horizons (flat ≥ 70 %);
  compare macro-F1 and hit rate instead.
- **Correction.** An earlier revision of this file said `binance_btcusdt_smoke` "is now a subset of the day
  set and is no longer reported". That was wrong when written: at the time the smoke dataset had been
  byte-identically overwritten by the full-day conversion (same paths, same sha256), so it *was* the whole
  78-minute day, not a subset — the §6 predictions and the notes.md row about the "8-minute smoke set" refer
  to a still earlier conversion of it. The Data Engineer has since rebuilt it as a genuine view, the 298.6 s
  gap-free window above, and it is reported again as the smoke tier only.
